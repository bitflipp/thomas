# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

TypeScript runs directly on Node (≥ 22.18, type stripping; no build step); `tsc --noEmit` only checks the types (`tsconfig.json`, strict, `erasableSyntaxOnly`), it is part of `npm run lint`. Formatting and linting: Biome (`biome.json`). PDF output needs `rsvg-convert`.

```
npm test                                          # all tests (node --test test/)
npm run lint                                      # biome check (format + lint + import order, all rules are errors) + tools/blanklines.ts + tsc --noEmit
npm run typecheck                                 # tsc --noEmit alone (tsconfig.json; strict, nothing is emitted)
npm run lint:fix                                  # apply safe fixes, formatting and missing blank lines
node --test --test-name-pattern="ledger" test/    # a single test by name
node src/cli.ts render test/fixtures/study.txt out/study --pdf     # -> out/study-N.svg + .pdf
node src/cli.ts check test/fixtures/study.txt --collisions --mark out/mk   # list overlaps; out/mk-N.svg boxes them in red
node src/cli.ts import piece.musicxml out/piece.txt             # MusicXML -> text format
node src/cli.ts check <file>                      # validate measure lengths
node src/cli.ts import-rendition project.json score.txt out.txt   # take a Pianizer rendition over into a score (--tolerance <quarters>, --force)
python3 tools/crop.py out/study-1.svg x y w h out.png [px]      # render a region (staff spaces) to PNG
npm run ui                                        # editor UI (Vite dev server, ui/)
npm run ui:build                                  # build the UI into out/ui; any static server (`python3 -m http.server -d out/ui`) runs it in a browser, no Electron
npm run app                                       # build and start the desktop app (Electron); `just run-electron`
just install-desktop                              # build the app and install a GNOME launcher + icon under ~/.local/share (points at this checkout)
npm run icon                                      # regenerate build/icon.svg + icon.png (tools/make-icon.ts)
```

`tools/blanklines.ts` checks the blank lines Biome does not (see Comment and blank-line style below); `lint:fix` repairs them.

Biome enforces the type-stripping constraints (`noEnum`, `noParameterProperties`, `useImportType`) and bans `!` non-null assertions: use `must(x)` from `src/util.ts` (throws on a violated invariant). `noDelete`, `noParameterAssign` and `useDefaultSwitchClause` are off on purpose (optional model fields must be absent, not `undefined`; numeric code reassigns parameters; switches are checked by the types).

Because `node` strips types only: no enums, no constructor parameter properties, and imports need the `.ts` extension.

## Architecture

Pipeline: text/MusicXML → `Score` model → `prepare` → per-measure spacing → line breaking → justification → drawing into per-staff primitive lists → spanners/marks → system finalization → pagination → SVG (`render.ts`).

- **`src/model.ts` is the source of truth.** Everything is in integer ticks (`PPQ = 3360` per quarter). A voice is a tree of `Item`s (events, `TupletGroup`, `BeamGroup`), flattened by `flattenVoice`. Marks (dynamics, hairpins, pedal, ottava, clef changes, tempo) hang on events: `Event.marks` at the event's start, `Voice.end` at the end of the measure (stops only). Their ticks are derived: `marksOf(staffMeasure)` (cached per object, never call it on an Immer draft; use `collectMarks` there) gives the tick-based `Mark`s that the engraver and playback use, each with its address (`voice`, event `idx`, `k`). `anchorMarks` hangs timed marks (MusicXML, `@` mark lines) on events. Hairpins/pedal/ottava are start/stop pairs matched later across measures and systems; the editor's `tidy()` (in `commands.ts`) drops a hairpin that lost an end.
- **Pickup and short measures** (`Measure.length`, ticks; `length=1/4` in the text format, `implicit="yes"` in MusicXML): the length of a measure is always `lengthOf(score, mi)` (own length, else the time signature's `measureTicks`), never `measureTicks(timeAt(...))` directly. A pickup is a first measure with a length: `measureLabel` numbers it 0 (the writer emits `m0`, the printed measure numbers and the UI use the label). `setMeasureLength` (Measure tab, Length) refits the voices; `setTimeSig`/`setTimeSigRange` keep a shorter length and drop one that is no longer shorter. The beat grid of a pickup is aligned to its end: `beatPhase(score, mi)` (`beams.ts`, a first measure with a length only) shifts the beats the automatic beaming counts (`phase`, the last parameter of `beamGroups`, `beamLinks`, `beamModes`, `planBeams`, `simplifyBeams`), the engraver, the editor, the Properties panel and the MusicXML importer pass it. The Expression pane's ruler and tooltips use `MeasureSpan.label` and count beats from the downbeat of the bar (`shift`). Not done yet: a "split here" command.
- **Lines** (`EventBase.lineStart`/`lineStop`, `&`/`;` in the text format): a straight line between two notes that may be in different voices or staves. An end may carry `head` (`LineStart.head`, `LineStop.head`: the index of one chord pitch, `<c3 g3;>` in the text format); without it the engraver aims at the centroid of all heads, with it at that head (`drawLink` puts each end nearest to the target that keeps clear of the note's heads, stem and accidentals). The editor's line tool and `lineSelection` attach to the clicked or selected head (`pi` of the ref). Matching is score-wide by id in time order (`pairLines`, `lineEnds` in `model.ts`), not per voice like slurs; `tidy()` drops an end whose partner is gone (`dropLooseLines` in `commands.ts`). The engraver draws one only when both notes are in one system (`linkUnits`/`drawLink` in `spanners.ts`, kind `link`, nothing goes into the skyline); a system with line ends pins its staff gap first (`hasCrossStaffNotes`) because a line between staves needs the final distance. The editor tool refuses notes of different systems using `Layout.systems` (`sameSystem` in `ui/interact.ts`).
- **Grace notes** are `NoteEvent.graces` (zero duration, attached to the note they precede; `\acc{}`/`\grace{}` in the text format, `<grace>` in MusicXML). The engraver carries them as `EvL.graces` (`GraceL`): `layoutColumnStaff` reserves their width on the left of the column (`dx`, `accX`), `drawGraces` in `draw.ts` draws them at `GRACE_SCALE`. Playback plays slashed ones just before the beat, others on the beat taking time from the note. The editor edits them in the Properties panel for a single selected note (`addGrace`, `updateGrace`, `transposeGrace`, `removeGrace` in `commands.ts`); graces are `Ref`s of their own (`{ t: 'grace', gi }`, found through `Prim.gr`, which `tagGrace` sets): click one to select it, drag it to a new pitch, Up/Down step it, Delete removes it, the Grace tool (`addGraceAt`) places one in front of the note at the pointer, and the Properties panel (`GraceSection`, `GraceControls`) edits value, slash, steps and chord tones (`addGraceTone`, `removeGraceTone`).
- **Mordent and turn** are `NoteEvent.ornament` (`+mo`/`+mi`/`+tu`/`+ti`, `<mordent/>`, `<inverted-mordent/>`, `<turn/>`, `<inverted-turn/>` in MusicXML), drawn with the trill and fermata (kind `ornament`) and played by `addOrnament` as quick neighbor notes in the key.
- **Trill lines** are start/stop marks (`{type:'trill'}`, `{type:'stop', of:'trill'}`; `\trill`/`\trilloff`, `<wavy-line>`) matched like pedal and ottava (the next stop, a new start ends the old line); `addTrillLines` in `marks.ts` draws the sign and `wiggleTrill` segments above the staff, playback trills every note starting under one (`trillLinesOf`). The editor places them with the Trill tool (`addSpanOver`, kind `trill`).
- **Fermata and trill** are plain fields (`EventBase.fermata`, `NoteEvent.trill`; `+fm`/`+tr` in the text format, `<fermata>`/`<trill-mark/>` in MusicXML; a fermata has an optional `fermataShape` (`short`/`long`, `+fms`/`+fml`) and `fermataBelow` (`_`), drawn below the heads and stem in `drawOrnamentsOfStaff`), drawn by `drawOrnamentsOfStaff` in `draw.ts` above the heads, stem and articulations (kinds `fermata`/`trill`). `NoteEvent.trillAcc` is the upper note's alteration, drawn small above the mark. Playback alternates a trill with the upper neighbor in the key (`addTrill`), or carrying `trillAcc` and stretches a fermata event in the tempo map (2x, short 1.5x, long 3x) (`fermataSpans`).
- **Repeats and voltas**: `Measure.repeatStart` and `barline: 'repeat-end'` (`start=repeat`, `barline=repeat-end` in the text format, `<repeat>` in MusicXML); `drawRepeatBar` in `finalize.ts` draws the thick-thin lines and dots at a measure boundary (`:||:` when an end meets a start; `REPEAT_WIDTH` in `spacing.ts` reserves the room). `Measure.ending` (numbers of the passes, `ending=1,2`) puts a measure under a volta: `drawVoltas` in `engrave/volta.ts` draws one bracket per run of equal endings above the first staff, closed by a hook when the last measure is a `repeat-end`, before the other marks so they stack above it. Playback ignores both.
- **Staff labels** (`StaffDef.name`/`abbr`, `page.labelsFirst`/`labelsLater` = `full`|`abbr`|none, `labelSize`; `labels=full,abbr labelsize=2` and `name=`/`abbr=` in the text format, `part-name`/`part-abbreviation` in MusicXML, only on the first staff of a part): `src/engrave/stafflabels.ts`. `leftRooms` gives the room left of the staves (brace area, widest label of the first system, widest of the others, estimated by `textWidth`); `engrave` makes every system's line `later` wide and the first one `first - later` narrower, `planSystems` gets that as `firstIndent` and `paginate` shifts system 0 by it (`PaginateOptions.firstIndent`, negative when its labels are shorter), so `Layout.systems[0].x0` differs. `drawStaffLabels` (from `finalizeSystem`, kind `stafflabel`) right-aligns the text left of the brace area at x < 0 and centers a label over the whole group when it opens a group whose other staves have none. The editor sets them with `setStaffName`/`setStaffAbbr`/`setStaffLabels` (Properties: Staves and Page).
- **Lyrics** are `NoteEvent.lyrics` (`Syllable`: verse, text, syllabic, extend; `"Ly-"v2"…"_` after the note in the text format, `<lyric>` in MusicXML). Spacing keeps syllables apart in `separateLyrics` (`spacing.ts`: `minFrom` between the syllable columns of a staff and verse, with `HYPHEN_ROOM` where a word goes on; widths are estimated by `lyricWidth`, there are no font metrics). `drawLyrics` (`engrave/lyrics.ts`) draws one row per verse under a staff at a common baseline per system, below the skyline, with hyphens and extenders, before the other marks so that they stack outside it. The editor enters them with `setSyllable` (`commands.ts`, which keeps `syllabic` consistent along the verse by `normalizeVerse`) and `neighborNote` (`src/editor/lyrics.ts`); the Lyric box in Properties (`LyricRows`) is a typing stream (Space next note, `-` hyphen, `_` extender, Backspace back). Not done: a lyric tool on the score, a hyphen or extender over a system break beyond a short stub, verse numbers.
- **Multi-measure rests** (`page.multiRests`, `multirests=on`; `src/engrave/multirest.ts`) are an engraving decision only: the measures stay in the model. `findMultiRuns` finds runs of measures whose staves all hold one whole-measure rest (no marks except at the start of the first, no key/time change or forced break after the first). In `engrave` the first measure gets a wider `MeasureSpacing` (`multi`), the others a zero-width one (`absorbed`); `prep.multi`/`prep.absorbed` tell the drawing code (`drawMultiRest`, skipped measures in `drawSystemNotes`, hidden inner barlines and measure numbers in `finalize.ts`). `planSystems` never cuts inside a run. The layout keeps one zero-width entry per absorbed measure.
- **`src/beams.ts`** holds the beaming rules (explicit `BeamGroup`s + automatic per-beat grouping) used by the engraver and by the importer, which drops explicit groups, `noBeam` flags and tuplet brackets that the automatic choice reproduces (`simplifyBeams`, `simplifyTupletBrackets`). The editor's per-note beam modes (auto / none / start / join, MuseScore-style) are derived from the explicit groups and `noBeam` flags (`beamModes`) and written back by `planBeams` + `setBeamMode`, which rebuilds a voice's groups and flags; beams stay within one measure, so a first note cannot be joined to the previous measure.
- **`src/textformat.ts` must stay lossless**: `write(parse(text)) == text` and `parse(write(score))` deep-equals the model; `test/roundtrip.test.ts` checks it on `test/fixtures/study.txt`. When adding a model field, update the writer, the parser, and the importer together. `FORMAT.md` is the grammar and is the user-facing spec.
- **`src/musicxml.ts`** (entry: metadata, page, parts; `musicxml-measure.ts` reads one measure of a part into `RawNote`s and timed marks, `musicxml-voice.ts` builds a voice's item tree from them, `musicxml-raw.ts` has the shared types) drops all MuseScore positions and (by default) its automatic breaks; voices are renumbered per staff. Tuplets and beams are rebuilt from start/stop ranges into nested groups.
- **Engraver (`src/engrave/`)**: all units are staff spaces, y points down, staff-local y=0 is the top line, and staff positions count half-spaces above the bottom line (`posToY` in `prep.ts`).
  - `prep.ts` builds `EvL` records (written positions after ottava/clef, accidentals, beam groups, stem directions) shared by all later phases. Layout results are written back onto these objects (`e.x`, `heads[].dx`/`accX`/`shared`, `shiftDx`, `geomOf` WeakMap in `draw.ts`).
  - **Cross-staff notes** (`Event.staff`): `EvL.staff` is the staff the heads are drawn on, `EvL.home` the voice's. `StaffMeasureL.evs` lists what is drawn on a staff, `.voices` the voices of the staff with all their events. Beams/tuplets/slurs follow the voice. A beam over two staves (`BeamL.cross`) is drawn by `drawCrossBeam` for the staff gap `ctx.gap`, which `staffgap.ts` (`drawNotesFixingCrossStaffGap`) iterates until it fits (`gapNeed`) and then pins; its prims stay out of the skyline.
  - `spaceMeasure` runs **twice per measure** (normal and "first in system", which skips a clef change at tick 0). Its mutations of `EvL`/`HeadL` must therefore be idempotent (`layoutColumnStaff` resets them first); a bug here once doubled head offsets.
  - Spacing is `x_j = max(prev + f·ideal, collision constraints)`. `f` is solved by bisection per system; `planSystems` (DP in `linebreak.ts`; `justify.ts` solves `f` and builds the `SysCtx`) allows compression down to `COMPRESS`.
  - Drawing is staff-local per system; `spanners.ts` (ties, slurs) and `marks.ts` (dynamics, hairpins, pedal, ottava, tempo, text) run after all systems exist (they can cross systems) and use `Skyline` boxes for collision avoidance. `finalize.ts` then fixes staff distances from the skyline extents (`staffgap.ts`) and draws staff lines, signatures (`signatures.ts`), measure numbers, barlines and braces; `paginate.ts` places the systems on pages and records the editor `Layout`. `system.ts` is only the `engrave` orchestrator.
- **Incremental engraving** (`EngraveCache`, `createEngraveCache()` in `system.ts`; the editor keeps one across edits): `engrave(score, { cache })` must give exactly what a fresh `engrave(score)` gives, and `test/incremental.test.ts` checks that after random edits (and with mutants of each rule it must fail). What is reused:
  - `prepare` and `spaceMeasure` per measure (`MeasureEntry`): keyed by the `Measure` object (Immer keeps untouched ones identical) plus a signature of the state carried into it (clef, ottava, key, time, ties). Anything that makes a measure's records depend on something new must go into `measureSignature`.
  - A system's drawn notes (`reusable` in `system.ts`): same measure entries, plan, width. Its `ctx.base` says where the notes end; spanners and marks are drawn after and can be taken off again (`rewindToNotes`, `ctx.ts` for marks).
  - Ties and slurs (`planSpanners` in `spanners.ts`): units with a key (end events, slur side) and the systems they touch. A system is redrawn if it is dirty, its unit keys changed, or a unit touching it touches a redrawn system. Marks are always redrawn for every system (cheap). A tie or slur that reads something beyond its own ends and systems must put it in its key.
  - A system's finalized primitives (`FinalSnapshot`, compared with the primitives it had before finalizing) and their placed copies (`placedPrims` in `paginate.ts`); `Engraved.placed` is what `buildHitIndex` caches its targets by.
  - Owner tags (`Prim.o`) must be stable across runs (`slurOwner`, `pieceOwner`), or unchanged systems compare unequal. Path prims are moved by `dx`/`dy` (`shiftPrim`), not rewritten; everything that reads a path's `d` must apply them.
- **Ghost rests** (`EngraveOptions.ghostRests`, `Prim.ghost`): the editor engraves hidden rests (`s`) as faint rest glyphs tagged `rest`, so that they can be hovered, clicked and marquee-selected. They stay out of the skyline and spacing, `pageToSvg` omits them unless `ghosts: true`, and the UI leaves them out when printing. The option is part of the cache's `scoreKey`. Never use it for output or collision tests.
- **Collisions (`src/engrave/collide.ts`)**: every prim carries `k` (kind), `o` (owner) and `g` (groups) tags set where it is pushed (`tagFrom`/`oid` in `scene.ts`). `findCollisions(pages)` reports any overlap not in `ALLOW` (pairs of kinds, scope `own`/`any`); staff lines and untagged prims are ignored. Pairs of box-like shapes are compared by bounding box, others by outline. `test/collisions.test.ts` runs it on the study fixture; `KNOWN` there lists tolerated leftovers. New drawing code must tag its prims.
- **`src/smufl.ts`**: Leland outlines via opentype.js; `CP` maps glyph names to codepoints. `checkCodepoints()` verifies the table against the font metadata advances; run it when adding glyphs.

## Editor (`src/editor/`, `ui/`)

- **Headless editing, `src/editor/`** (testable with `node --test`, `test/editor.test.ts`):
  - `commands.ts`: pure `Score -> Score` functions on Immer drafts. A refusal throws `EditError` (message for the user). Every command leaves each voice exactly as long as its measure; `edit()` re-runs `tidy()` on the touched measures (dissolves beam/tremolo groups that lost notes, drops dangling slurs).
  - Copy and paste (`copyEvents`, `pasteEvents`, `copyMarks`, `pasteMarks` in `commands.ts`; the clipboard is in `ui/keys.ts`): a `Clip` holds the events (graces, ornaments and lyrics are event fields) with the marks that stay complete, spans that run past the copy bring their stops as `tail` (hung on the event after the pasted ones), and pasted hairpins get free ids.
  - `voice.ts`: `putEvent` writes an event at a tick: it overwrites what is there, leftovers become rests (`splitTicks`), a tick inside a tuplet descends into it (positions are *written* ticks per level), `overwrite` refuses to cut a tuplet/tremolo in half.
  - `addr.ts`: `Ref`s name things by (measure, staff id, voice id, flat event index), not by object, so they survive edits; `indexScore` maps model objects to addresses.
  - `context.ts`: clef/ottava/key/accidentals in force at a position, staff position <-> pitch, transposition.
  - `similar.ts`: "select similar", the refs of every element like a given one (same mark type, all notes, all rests ...), which the Properties panel edits together; with `by` ('fermata' | 'trill' | 'grace') the events carrying that ornament.
  - `hit.ts`: `buildHitIndex(score, engraved)` turns prims into targets via the engraver's tags (`Prim.r` = model object, `Prim.n` = head index / slur id), `hitTest`, `marquee`, `measureAt`, `snapTick` (uses `Engraved.layout`: per staff-measure x/y and column positions).
- **UI, `ui/`** (Vite + Preact + signals + CodeMirror 6; `npm run ui`): the main area has three modes (`mode` in `state.ts`, the selector at the right of the toolbar): Score (palette, score pane, Properties, which the View menu and Ctrl I show or hide), Expression (Ctrl Space) and Text (Ctrl E), each over the whole width; the score pane stays mounted, collapsed, in the other two, and the middle of the toolbar shows the controls of the mode. `state.ts` holds the score signal with undo history (`commit`/`run`), selection, tool settings, and the engraving effect (full re-engrave per edit, 70-200 ms on the big piece; one-system scores are re-engraved with `fillLast`). `actions.ts` holds the actions on the selection shared by the palette, Properties and shortcuts (each runs a command and commits one undoable step; an `EditError` goes to the status line), `pickers.tsx` the duration/accidental pickers both panels share, `Shortcuts.tsx` the `?` dialog (documentation only; the bindings are in `keys.ts`). `interact.ts` is the pointer state machine (select/marquee/drag head/note and rest input/spans/marks/tuplet; there are no context menus, every action is in the Properties); `ScorePane.tsx` renders pages (SVG generated only near the viewport and only when the page's selection changed) with an overlay for ghosts; `Palette.tsx`, `Properties.tsx`, `keys.ts`, `TextPane.tsx` (the score as text, the Text mode, Ctrl+E; edits re-parse after a pause into one undoable commit; the score selection is marked in the text through `writeTextMap`, which returns the text with the ranges of events, marks, tuplets and measures, keyed by `refKey`).
- In dev builds `window.__t` exposes the state signals (`score`, `hit`, `engraved`, `selection`, ...), used for scripted tests with `playwright-core` + the system Chromium (`executablePath: '/usr/bin/chromium'`, `--no-sandbox`).
- The engraver runs in the page: `ui/fonts.ts` feeds Leland to `setSmuflSource`; `loadSmufl()` is a lazy facade (and `D` in `draw.ts` a lazy proxy), so engraver modules may touch the font at import time. Nothing under `src/` may import `node:*` at top level. UI files are `.tsx` and Vite-only.
- **Parallels check** (`src/analysis/parallels.ts`, `findParallels(score, kinds)`): consecutive fifths, octaves and unisons (unisons only between voices of different staves; a piano part doubling a voice is flagged like any other, on purpose) between any two voices (key `staff/voice`, so across staves too) or inside one chord, at successive attacks or across a rest both voices share; tie continuations are not attacks, grace notes are ignored, an octave inside one voice is a doubling, and the lower note of an octave doubling within a staff is dropped before anything is compared (`withoutLowerDoublings`), so a doubled line is reported once. Violations that share a note form one group, numbered in score order; the result addresses notes by `EvAddr` + head index, so it is a pure function of the score. Each group has a `level`: `certain` when the notes of both intervals continue into each other in every reading of the voice-leading, `possible` when only in some (`readings`, `VoiceIndex.continuation`): separate voices, chords of equal size (note by note) and the outer notes of a chord are certain; a chord that goes on to one of another size has one reading per way of merging or splitting notes (four into three: three readings), so an inner pair is `possible`, and a pair no reading leads into the interval is dropped. Groups are formed per level (`Candidates.split`), so a possible violation never colors a certain one. The layer shows `possible` as `warn` (orange), `certain` as `error` (red); `thomas check --parallels` marks them "(possible)". The editor turns it on as a layer (below): the notes are drawn in the warning color by `PageView` (a render-time color only, nothing in the engraving or the cache; print stays black). `thomas check --parallels` lists them. Not done: other kinds (hidden/direct fifths), dismissing a single violation.
- **Layers** (`ui/layers.ts`, `ui/Layers.tsx`, `ui/Findings.tsx`): analyses that point at places in the score, as opposed to display options (voice colors), which stay in the View menu. Exactly one layer or none is chosen (`activeLayer`, radio buttons in the menu; the layers are independent analyses, so they share colors); a `Layer` has `on` (whether it is the chosen one) and a computed signal of `Finding`s (layer id, label, voices, measure and tick, head refs), a pure function of the score and the layer's settings; `layers` is the registry (parallels); a finding has a severity (`error` red, `warn` orange) and `layerNotes` maps heads and whole events to the color they are painted (`LAYER_COLORS`; an error wins over a warning), which `ScorePane` uses. Everything that shows findings reads the merged `findings` (score order) or `layerNotes` (heads and whole events to draw in the warning color, read by `PageView`): `FindingsSvg` in `ScorePane.tsx` draws each finding as translucent outlines (`Finding.shapes`: for the parallels one quadrilateral through the four heads of each interval, `ParallelGroup.intervals`, so overlapping findings stack; a shape over a system break is two segments). The outline under the pointer (`hoverShape`; `shapeAt` in `layers.ts` hit-tests the `shapeParts` from the pointer handler, smallest outline wins, since the overlay takes no pointer events) is drawn stronger while the others fade, and the flagged notes outside it are recolored black in place (`PageView`) (`PageView`), and a tooltip (`FindingTip`) names kind, voices and place, F8 / Shift+F8 (`stepFindings` in `Findings.tsx`, which chooses the first layer if none is) select the next or previous finding and scroll to it (`reveal` in `interact.ts`), and the Overview strip marks their measures. The Layers menu (`Layers.tsx`) has a radio button per layer. A new layer is an entry in `layers`.
- **Expression and performance** (`NotePitch.vel`/`shift`/`gate`, `Score.performance`; `{v=,s=,g=}` after a pitch and the `tempocurve`/`sustain`/`soft` statements in the text format, see `FORMAT.md`): how the score sounds, kept in the model so that copy, undo, `tidy()` and the text format carry it. A head's velocity replaces the one from the dynamics, `shift` (milliseconds) moves the attack after the tempo map (`toMessages`; it adds to the roll of `\arp`), `gate` scales the sounding length notation gives; all are read in `addChord` and `addTremolo` and put on each `Note` (`Note.head` says which head it came from, `Note.shift`). Only the first head of a tie chain counts. The `Performance` curves are anchored by measure and tick (`Pos`), not absolute ticks; `sequence.ts` converts them. The tempo ratio is a monotone cubic spline (`playback/curves.ts`) folded into `tempoMap` (numeric integration per segment, bisection for `secToTick`); the sustain pedal is a line sampled per controller step (`rampEvents`), the una corda binary. Pedals go to every channel in use. Editing: `src/editor/expression.ts` (heads: `setHeadValues` is the one primitive, `setVelocity`/`setShift`/`setGate`, `nudgeVelocity`/`nudgeShift`, `rampVelocity` with the easing shapes, `rollChord` (heads that start together, also across voices and staves, get shifts that spread them over a span; the shifts are worked out from where the notation puts the notes, so a notated `\arp` is not rolled twice; tremolo, trill and ornament heads are left out), `resetExpression`; `headInfos` reads what each head sounds like from the playback sequence, `selectedHeads` expands refs (an event, a head, a measure) into heads) and `src/editor/performance.ts` (curve points and una corda regions in absolute ticks, converted to `Pos`; `fitPerformance` runs in `commands.ts`'s `edit` after every command and moves points to the end of a measure that shrank or drops them with a measure that went; `moveAnchorsOnInsert`/`moveAnchorsOnDelete` are called by `insertMeasures`/`deleteMeasures`). Neither goes through `edit`/`tidy` (nothing to tidy); both are tested in `test/expression-edit.test.ts`.
- **Expression pane** (`ui/Expression.tsx`, `ui/expression.ts`, `ui/exprDraw.ts`; toolbar button and Ctrl Space (or Ctrl M), `showExpression`, `exprView` in `state.ts`): all expression editing is done here, none in Properties. A canvas shows the ruler (click or drag seeks), the roll (every sounding note of the playback sequence at the tick it is heard, so shifted attacks are shown shifted; the rows are a piano's 88 keys at a fixed height, `ROW_H`, as in Pianizer's roll: zooming changes only the width of the notes (Ctrl + wheel), the wheel pans sideways, Alt + wheel and right-drag (or middle-drag) pan up and down and sideways, `exprView.top` is the vertical scroll and `placeView` puts it at the middle of the pitches at the start of the piece; a bar's color is its velocity on a blue-teal-amber-red ramp, `velocityColor` in `exprDraw.ts`, with the number inside) and, as in Pianizer, three lanes stacked under it that are always in view (`geo` gives each its band, `laneRects`): the tempo curve, the sustain pedal (click adds a point, drag moves, Delete removes) and the una corda regions (drag paints, edges and body drag, Delete removes), so notes and pedals are edited together. There is no lane for the values of the notes: velocity is the color of a bar, shift its place and gate its length, and all three are set with tools on the selected notes (`NoteTools` in `Expression.tsx`: Set, Ramp, Delta, Shift, Gate and Roll, keys 1 to 6, each a window at the pointer; there are no buttons for them; the windows of Set, Shift and Gate also take the value off the notes again). A press selects the lane by where it lands; `pointSel` (the selected curve point or region) decides whether Delete and the arrow keys act on it or on the selected notes (Delete only on a point). Heights of the curve lanes are Pianizer's (150, 75, 24 px, `LANE_HEIGHTS`). The lanes are separated by a gap (`LANE_GAP`) and each has its own hue (`--lane-tempo`, `--lane-sustain`, `--lane-soft`, read into `Colors.lane`) for its curve, points, fill and label. Clicks and drags in the curve lanes snap to the grid chosen in the toolbar (`snap`, `SNAPS`, counted from the barline; Alt: none); a right click that does not move removes the nearest point or the region under it (a right drag pans). While the view is open the main toolbar holds, in place of View and Layers, only the snap grid (`ExpressionTools`, which also mounts `NoteTools`); the value of a selected point is changed by dragging or ArrowUp/Down; its zoom controls and Ctrl +/- zoom the roll (`zoomRoll`, `fitRoll`), and the palette, Properties, MIDI in and the engraving status are hidden. There are deliberately no Reset/Clear buttons (Delete does the per-selection job). Notes are selected in the roll (click, Shift or Ctrl adds, a box selects) and the selection is the score's own, so the score pane and the pane show it together; a selection made in the score brings the view to it, the view follows the playhead while playing and `revealMeasure` (the overview strip, Ctrl G) moves it. A gesture shows its result in `draft` (the pane's playback and picture are derived from `draft ?? score`) and commits once on release, so each is one undo step; the canvas takes ArrowUp/Down and Delete itself (`onKey`) so that they do not reach the score's shortcuts. It was tested with `playwright-core` against the Vite dev server, not by an automated test.
- **Importing a Pianizer rendition** (`src/rendition.ts`, `thomas import-rendition`): the notes of a Pianizer project file are matched to the sounding notes of the score that have a head (`Sequence.notes`, per pitch, by an optimal order-preserving matching of onsets within `tolerance` quarters), a unison written in several voices is matched through its longest head, the others copy velocity and shift but keep their own gate (unless the project kept a note for each); the differences become `vel`, `shift` (ms, measured on the score's own tempo map including the imported tempo curve) and `gate` (only when the end is more than 20 ms from the notated one), and the three curves become `Score.performance` (the sustain curve gets a first point where the project held its first value). Existing expression and performance are replaced; muted notes cannot be carried over; fewer than 80% matched means another piece (the CLI writes nothing without `--force`). It has only been tested on projects built from the score itself, not on a real Pianizer file.
- **Overview strip** (`ui/Overview.tsx`, under the score pane): one bar per measure (width by length, height by note count) with the system-start numbers on a ruler, ticks for landmarks (tempo and text marks, key/time changes, repeats and voltas: `landmarksOf`), the visible part of the score as a frame (`visibleMeasures`, from `Layout.systems`), the selection, parallels findings and the playhead (`playMeasure`); at its right (Score mode only) the number of systems and pages and the time of the last engraving (`timing`), which used to be in the toolbar. A click or drag scrolls the score there at once (`revealMeasure` in `interact.ts`). Hovering shows a popover with the system of the measure under the pointer and the ones before and after it, cropped out of the real engraving (`systemPreview`: `pageToSvg` with its `crop` option over `Engraved.placed`, cached per primitives array, so an unchanged system is not drawn again; measured at under a frame per hover on a 400-measure piece). Ctrl+G opens the go-to-measure prompt. Not done: page thumbnails (they would have to be drawn in idle chunks: all pages at once took about 0.75 s in the browser).
- **Playback**: `src/playback/sequence.ts` (headless, tested) turns a `Score` into timed MIDI messages (tempo map, ties merged, velocity from dynamics, hairpins ramp to the next dynamic (`readDynamics`), channel per staff; the pedal marks of the notation are never played); `ui/player.ts` sends them to a Web MIDI output (chosen in the menu of the Play button, its ▾ or a right click: `PortMenu` in `ui/PortMenu.tsx`, which asks for access on opening; MIDI in has the same menu for its input) with a look-ahead scheduler and owns `playTick`/`playhead` (absolute ticks, kept across stops so play resumes). Edits while playing rebuild the sequence and carry on; a new document (`docId`) resets to the start. No built-in synth (decided against).
- Range selection of measures: the selection holds `measure` refs (Shift-click in `interact.ts` grows a run from the last clicked measure, Ctrl adds one); the Measure tab edits the whole run (`setKeySigRange`/`setTimeSigRange`, barline at the end, repeat start and break at the start, voltas on all), Ctrl+C/V copy and paste the staff contents (`copyMeasures`/`pasteMeasures`, hairpins renumbered, same lengths required).
- **Note input and the caret** (`ui/caret.ts`, `Caret`/`caret`/`setTool` in `state.ts`): note input (`entering()`, the only input tool; there is no rest tool and no entry by clicking) has a caret (measure, staff, tick; the voice is the palette's `voice`, so changing voice keeps the position in time). A click puts the caret (`placeCaretAt` in `interact.ts`), a click on a note selects it and leaves input. The pitch of the next note is chosen before it is entered (`nextPitch` in `state.ts`; null: the top of the note before the caret, else middle C, `pitchAt`; a click that puts the caret and `setTool` clear it): Up/Down step it on the staff with the alteration from key and bar (`stepNext`, `plainAlter` in `context.ts`), Ctrl+Up/Down an octave (`octaveNext`; in select mode the selection, by steps so the spelling stays), `+`/`-` and the accidental buttons alter it (`alterNext`, `pickNextAccidental`, `nextAccidental` for the palette). W enters it (`enterNext`) and keeps its pitch for the next note, so a line is entered as arrows and W; Shift+W adds it to the note just entered (`addChordTone`, `chordTone`; a third above the top when the chord has it already, and in select mode a third above the selected note, of which only the new head is then selected). With Shift held, the same keys change the tone Shift+W would add, starting from the one the preview shows on the chord (`changeNext` with `chord`; steps and octaves skip pitches the chord already has); the accidental keys are + / * and - / _ with Shift, so that both the German and the US layout work. Nothing is selected while notes are entered, so the note about to be entered is the only one drawn in color. R enters a rest, Shift+1 to 4 choose the voice, S opens and closes a slur at the note entered last (`slurFrom`, shown in the label), arrows/Home/Backspace move the caret (and keep the next pitch). In input the duration and dot buttons set only the next note (`editsSelection`); in select mode they change the selection, and the next note's duration and voice follow the selection (`effect` in `actions.ts`). `setTool` puts the caret on the first selected event and clears the selection. `moveToVoice` (`commands.ts`, Alt+1 to 4, "To vN" in Properties) moves notes to another voice of the staff at the same ticks (rests stay behind, refuses to land on notes or to move tuplet notes), `selectVoice` (Alt+Shift+1 to 4) selects a voice in the selected measures. There is no drawn caret: in input the score pane shows the would-be score (`preview`/`shown` in `state.ts`, `wouldBe` in `caret.ts`), the score with the next note in it (Shift held: added to the chord as Shift+W would), built by the same commands, so spacing, rests, beams and stems are what the entry will give; the engraving and the hit index are of `shown`, the new note is painted pale (`isPreviewNote`), `CaretSvg` labels it (and draws it in red over the score when the entry would be refused). Refs of the hit index name things in `shown` and the selection names things in the score: `realRef`/`shownRef` move a ref between them by the tick it starts at. `onKey` batches each key, so the would-be score is engraved once per key. Not done: ties across a barline when a note does not fit, tuplets from the keyboard.
- **MIDI keyboard input** (`ui/midiin.ts`, headless part `src/editor/stepentry.ts`): the toolbar's "MIDI in" button asks for Web MIDI access and listens to an input; every key enters a note of the chosen duration at the cursor (the first selected event, else the start of the first staff), spelled by the key signature (`spellMidi`), and moves the selection on (`advanceCursor` adds measures at the end); keys within 90 ms form a chord. Each key is one undo step; the note is sounded on the output opened by playback (`preview`). Not done: rests and ties from the keyboard, other voices than the selected one, recording in time.
- Not done: multi-staff-part scores beyond the model's own limits.

## Desktop app (`electron/`)

- The editor runs in a plain browser (the built UI from `out/ui` served by any static server) and in an Electron wrapper for the desktop. `ui/native.ts` is the one place that knows the difference: `window.native` (the preload bridge) in Electron, else the File System Access API or a file input and a download for open/save, `window.print()` for PDF, `beforeunload` for the unsaved flag. Keep new native features behind that interface with a browser fallback. `electron/main.ts` (window, MIDI permission, open/save dialogs, PDF via `printToPDF` with `preferCSSPageSize`, unsaved-changes prompt on close) and `electron/preload.ts` (exposes `window.native`; typed in `ui/native.ts`) are bundled by `tools/build-app.ts` (esbuild, into `out/app`; the main script is ESM, the preload CJS). The built UI is loaded from `out/ui` (Vite `base: './'`).
- File handling goes through `native` (see above): `openFile`/`saveFile` in `ui/App.tsx`, the path is `filePath` in `state.ts` (in a browser the file's name stands in for a path). Autosave to `localStorage` stays as crash recovery.
- Scripted checks: `_electron.launch` from `playwright-core` with `--no-sandbox`.

## Conventions worth knowing

- `test/fixtures/` holds the scores the tests load: `study.txt` is a short piece written for the tests (two staves, 14 measures; tempo change, slurs, ties, a line, tuplets, tremolo, a hairpin across a barline, a unison head shared by two voices, graces, ornaments, ottava, clef change, lyrics, repeat with voltas, a cross-staff beam) and `ornaments.txt` the ornament marks. Tests address its measures by index, so change a measure there only together with the test that names it. It must stay canonical text (`write(parse(text)) == text`) and free of collisions (`test/collisions.test.ts`).
- Engraving tests assert on emitted primitives (`engrave(...).pages[0].prims`), not on pixels. Visual checks are done by rendering and viewing crops; `out/` is git-ignored.

## Comment and blank-line style

- Every comment is a complete sentence that starts with a capital letter and ends with punctuation. The exception is a comment that starts with an identifier or code (`` `placed` holds ``, `x0 and x1 are read ...`, `eb2 in m33 ...`). This includes trailing comments on fields and statements (`// This is the voice id.`), not only block comments.
- Comments on functions (declarations, and arrow functions bound to a `const`) use `/** ... */`, not `//`. A `//` comment is for explaining code inside a body or for a section.
- No `// ---- name ---` banner headers. A section of a file starts with a plain `//` comment of a few lines that says what the section is for and how it relates to the rest, followed by a blank line, so that it cannot be mistaken for the doc comment of the first function below it.
- A file starts with a header comment (what the module is for, how it fits the pipeline), then a blank line, then the imports.
- Blank lines on the top level of a file (checked by `tools/blanklines.ts`, part of `npm run lint`): items are separated by exactly one blank line, except a run of one-line declarations without comments (imports, constants, type aliases); a doc comment sits directly above its declaration; a `/** */` comment is never left standing alone. Biome already collapses repeated blank lines and cleans up the edges of blocks; blank lines inside functions and classes are not checked.
