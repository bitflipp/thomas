# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

TypeScript runs directly on Node (≥ 22.18, type stripping; no build step); `tsc --noEmit` only checks the types (`tsconfig.json`, strict, `erasableSyntaxOnly`), it is part of `npm run lint`. Formatting and linting: Biome (`biome.json`). PDF output needs `rsvg-convert`.

```
npm test                                          # all tests (node --test test/)
npm run lint                                      # biome check (format + lint + import order, all rules are errors) + tools/blanklines.ts + tsc --noEmit
npm run typecheck                                 # tsc --noEmit alone (tsconfig.json; strict, nothing is emitted)
npm run lint:fix                                  # apply safe fixes, formatting and missing blank lines
node --test --test-name-pattern="ledger" test/    # a single test by name
node src/cli.ts render examples/gewitter.txt out/gewitter --pdf   # -> out/gewitter-N.svg + .pdf
node src/cli.ts check examples/gewitter.txt --collisions --mark out/mk   # list overlaps; out/mk-N.svg boxes them in red
node src/cli.ts import gewitter.musicxml examples/gewitter.txt     # MusicXML -> text format
node src/cli.ts check <file>                      # validate measure lengths
python3 tools/crop.py out/gewitter-2.svg x y w h out.png [px]      # render a region (staff spaces) to PNG
npm run ui                                        # editor UI (Vite dev server, ui/)
npm run ui:build                                  # build the UI into out/ui; any static server (`python3 -m http.server -d out/ui`) runs it in a browser, no Electron
npm run app                                       # build and start the desktop app (Electron); `just run-electron`
just install-desktop                              # build the app and install a GNOME launcher + icon under ~/.local/share (points at this checkout)
npm run icon                                      # regenerate build/icon.svg + icon.png (tools/make-icon.ts)
```

`tools/blanklines.ts` checks the blank lines Biome does not (see Comment and blank-line style below); `lint:fix` repairs them.

Biome enforces the type-stripping constraints (`noEnum`, `noParameterProperties`, `useImportType`) and bans `!` non-null assertions: use `must(x)` from `src/util.ts` (throws on a violated invariant). `noDelete`, `noParameterAssign` and `useDefaultSwitchClause` are off on purpose (optional model fields must be absent, not `undefined`; numeric code reassigns parameters; switches are checked by the types).

Because `node` strips types only: no enums, no constructor parameter properties, and imports need the `.ts` extension.

## Architecture

Pipeline: text/MusicXML → `Score` model → `prepare` → per-measure spacing → line breaking → justification → drawing into per-staff primitive lists → spanners/marks → system finalisation → pagination → SVG (`render.ts`).

- **`src/model.ts` is the source of truth.** Everything is in integer ticks (`PPQ = 3360` per quarter). A voice is a tree of `Item`s (events, `TupletGroup`, `BeamGroup`), flattened by `flattenVoice`. Marks (dynamics, hairpins, pedal, ottava, clef changes, tempo) hang on events: `Event.marks` at the event's start, `Voice.end` at the end of the measure (stops only). Their ticks are derived: `marksOf(staffMeasure)` (cached per object, never call it on an Immer draft; use `collectMarks` there) gives the tick-based `Mark`s that the engraver and playback use, each with its address (`voice`, event `idx`, `k`). `anchorMarks` hangs timed marks (MusicXML, `@` mark lines) on events. Hairpins/pedal/ottava are start/stop pairs matched later across measures and systems; the editor's `tidy()` (in `commands.ts`) drops a hairpin that lost an end.
- **Lines** (`EventBase.lineStart`/`lineStop`, `&`/`;` in the text format): a straight line between two notes that may be in different voices or staves. Matching is score-wide by id in time order (`pairLines`, `lineEnds` in `model.ts`), not per voice like slurs; `tidy()` drops an end whose partner is gone (`dropLooseLines` in `commands.ts`). The engraver draws one only when both notes are in one system (`linkUnits`/`drawLink` in `spanners.ts`, kind `link`, nothing goes into the skyline); a system with line ends pins its staff gap first (`hasCrossStaffNotes`) because a line between staves needs the final distance. The editor tool refuses notes of different systems using `Layout.systems` (`sameSystem` in `ui/interact.ts`).
- **Grace notes** are `NoteEvent.graces` (zero duration, attached to the note they precede; `\acc{}`/`\grace{}` in the text format, `<grace>` in MusicXML). The engraver carries them as `EvL.graces` (`GraceL`): `layoutColumnStaff` reserves their width on the left of the column (`dx`, `accX`), `drawGraces` in `draw.ts` draws them at `GRACE_SCALE`. Playback plays slashed ones just before the beat, others on the beat taking time from the note. The editor edits them in the Properties panel for a single selected note (`addGrace`, `updateGrace`, `transposeGrace`, `removeGrace` in `commands.ts`); graces cannot be clicked or placed on the staff yet.
- **Mordent and turn** are `NoteEvent.ornament` (`+mo`/`+mi`/`+tu`/`+ti`, `<mordent/>`, `<inverted-mordent/>`, `<turn/>`, `<inverted-turn/>` in MusicXML), drawn with the trill and fermata (kind `ornament`) and played by `addOrnament` as quick neighbour notes in the key.
- **Trill lines** are start/stop marks (`{type:'trill'}`, `{type:'stop', of:'trill'}`; `\trill`/`\trilloff`, `<wavy-line>`) matched like pedal and ottava (the next stop, a new start ends the old line); `addTrillLines` in `marks.ts` draws the sign and `wiggleTrill` segments above the staff, playback trills every note starting under one (`trillLinesOf`). The editor places them with the Trill tool (`addSpanOver`, kind `trill`).
- **Fermata and trill** are plain fields (`EventBase.fermata`, `NoteEvent.trill`; `+fm`/`+tr` in the text format, `<fermata>`/`<trill-mark/>` in MusicXML; a fermata has an optional `fermataShape` (`short`/`long`, `+fms`/`+fml`) and `fermataBelow` (`_`), drawn below the heads and stem in `drawOrnamentsOfStaff`), drawn by `drawOrnamentsOfStaff` in `draw.ts` above the heads, stem and articulations (kinds `fermata`/`trill`). `NoteEvent.trillAcc` is the upper note's alteration, drawn small above the mark. Playback alternates a trill with the upper neighbour in the key (`addTrill`), or carrying `trillAcc` and stretches a fermata event in the tempo map (2x, short 1.5x, long 3x) (`fermataSpans`).
- **Repeats and voltas**: `Measure.repeatStart` and `barline: 'repeat-end'` (`start=repeat`, `barline=repeat-end` in the text format, `<repeat>` in MusicXML); `drawRepeatBar` in `finalize.ts` draws the thick-thin lines and dots at a measure boundary (`:||:` when an end meets a start; `REPEAT_WIDTH` in `spacing.ts` reserves the room). `Measure.ending` (numbers of the passes, `ending=1,2`) puts a measure under a volta: `drawVoltas` in `engrave/volta.ts` draws one bracket per run of equal endings above the first staff, closed by a hook when the last measure is a `repeat-end`, before the other marks so they stack above it. Playback ignores both.
- **Lyrics** are `NoteEvent.lyrics` (`Syllable`: verse, text, syllabic, extend; `"Ly-"v2"…"_` after the note in the text format, `<lyric>` in MusicXML). Spacing keeps syllables apart in `separateLyrics` (`spacing.ts`: `minFrom` between the syllable columns of a staff and verse, with `HYPHEN_ROOM` where a word goes on; widths are estimated by `lyricWidth`, there are no font metrics). `drawLyrics` (`engrave/lyrics.ts`) draws one row per verse under a staff at a common baseline per system, below the skyline, with hyphens and extenders, before the other marks so that they stack outside it. The editor enters them with `setSyllable` (`commands.ts`, which keeps `syllabic` consistent along the verse by `normalizeVerse`) and `neighbourNote` (`src/editor/lyrics.ts`); the Lyric box in Properties (`LyricRows`) is a typing stream (Space next note, `-` hyphen, `_` extender, Backspace back). Not done: a lyric tool on the score, a hyphen or extender over a system break beyond a short stub, verse numbers.
- **Multi-measure rests** (`page.multiRests`, `multirests=on`; `src/engrave/multirest.ts`) are an engraving decision only: the measures stay in the model. `findMultiRuns` finds runs of measures whose staves all hold one whole-measure rest (no marks except at the start of the first, no key/time change or forced break after the first). In `engrave` the first measure gets a wider `MeasureSpacing` (`multi`), the others a zero-width one (`absorbed`); `prep.multi`/`prep.absorbed` tell the drawing code (`drawMultiRest`, skipped measures in `drawSystemNotes`, hidden inner barlines and measure numbers in `finalize.ts`). `planSystems` never cuts inside a run. The layout keeps one zero-width entry per absorbed measure.
- **`src/beams.ts`** holds the beaming rules (explicit `BeamGroup`s + automatic per-beat grouping) used by the engraver and by the importer, which drops explicit groups, `noBeam` flags and tuplet brackets that the automatic choice reproduces (`simplifyBeams`, `simplifyTupletBrackets`). Change the rules and `examples/gewitter.txt` needs regenerating or migrating. The editor's per-note beam modes (auto / none / start / join, MuseScore-style) are derived from the explicit groups and `noBeam` flags (`beamModes`) and written back by `planBeams` + `setBeamMode`, which rebuilds a voice's groups and flags; beams stay within one measure, so a first note cannot be joined to the previous measure.
- **`src/textformat.ts` must stay lossless**: `write(parse(text)) == text` and `parse(write(score))` deep-equals the model; `test/roundtrip.test.ts` checks it on the full piece. When adding a model field, update the writer, the parser, and the importer together. `FORMAT.md` is the grammar and is the user-facing spec.
- **`src/musicxml.ts`** (entry: metadata, page, parts; `musicxml-measure.ts` reads one measure of a part into `RawNote`s and timed marks, `musicxml-voice.ts` builds a voice's item tree from them, `musicxml-raw.ts` has the shared types) drops all MuseScore positions and (by default) its automatic breaks; voices are renumbered per staff. Tuplets and beams are rebuilt from start/stop ranges into nested groups.
- **Engraver (`src/engrave/`)**: all units are staff spaces, y points down, staff-local y=0 is the top line, and staff positions count half-spaces above the bottom line (`posToY` in `prep.ts`).
  - `prep.ts` builds `EvL` records (written positions after ottava/clef, accidentals, beam groups, stem directions) shared by all later phases. Layout results are written back onto these objects (`e.x`, `heads[].dx`/`accX`/`shared`, `shiftDx`, `geomOf` WeakMap in `draw.ts`).
  - **Cross-staff notes** (`Event.staff`): `EvL.staff` is the staff the heads are drawn on, `EvL.home` the voice's. `StaffMeasureL.evs` lists what is drawn on a staff, `.voices` the voices of the staff with all their events. Beams/tuplets/slurs follow the voice. A beam over two staves (`BeamL.cross`) is drawn by `drawCrossBeam` for the staff gap `ctx.gap`, which `staffgap.ts` (`drawNotesFixingCrossStaffGap`) iterates until it fits (`gapNeed`) and then pins; its prims stay out of the skyline.
  - `spaceMeasure` runs **twice per measure** (normal and "first in system", which skips a clef change at tick 0). Its mutations of `EvL`/`HeadL` must therefore be idempotent (`layoutColumnStaff` resets them first); a bug here once doubled head offsets.
  - Spacing is `x_j = max(prev + f·ideal, collision constraints)`. `f` is solved by bisection per system; `planSystems` (DP in `linebreak.ts`; `justify.ts` solves `f` and builds the `SysCtx`) allows compression down to `COMPRESS`.
  - Drawing is staff-local per system; `spanners.ts` (ties, slurs) and `marks.ts` (dynamics, hairpins, pedal, ottava, tempo, text) run after all systems exist (they can cross systems) and use `Skyline` boxes for collision avoidance. `finalize.ts` then fixes staff distances from the skyline extents (`staffgap.ts`) and draws staff lines, signatures (`signatures.ts`), measure numbers, barlines and braces; `paginate.ts` places the systems on pages and records the editor `Layout`. `system.ts` is only the `engrave` orchestrator.
- **Incremental engraving** (`EngraveCache`, `createEngraveCache()` in `system.ts`; the editor keeps one across edits): `engrave(score, { cache })` must give exactly what a fresh `engrave(score)` gives, and `test/incremental.test.ts` checks that after random edits (and with mutants of each rule it must fail). What is reused:
  - `prepare` and `spaceMeasure` per measure (`MeasureEntry`): keyed by the `Measure` object (Immer keeps untouched ones identical) plus a signature of the state carried into it (clef, ottava, key, time, ties). Anything that makes a measure's records depend on something new must go into `measureSignature`.
  - A system's drawn notes (`reusable` in `system.ts`): same measure entries, plan, width. Its `ctx.base` says where the notes end; spanners and marks are drawn after and can be taken off again (`rewindToNotes`, `ctx.ts` for marks).
  - Ties and slurs (`planSpanners` in `spanners.ts`): units with a key (end events, slur side) and the systems they touch. A system is redrawn if it is dirty, its unit keys changed, or a unit touching it touches a redrawn system. Marks are always redrawn for every system (cheap). A tie or slur that reads something beyond its own ends and systems must put it in its key.
  - A system's finalised primitives (`FinalSnapshot`, compared with the primitives it had before finalising) and their placed copies (`placedPrims` in `paginate.ts`); `Engraved.placed` is what `buildHitIndex` caches its targets by.
  - Owner tags (`Prim.o`) must be stable across runs (`slurOwner`, `pieceOwner`), or unchanged systems compare unequal. Path prims are moved by `dx`/`dy` (`shiftPrim`), not rewritten; everything that reads a path's `d` must apply them.
- **Ghost rests** (`EngraveOptions.ghostRests`, `Prim.ghost`): the editor engraves hidden rests (`s`) as faint rest glyphs tagged `rest`, so that they can be hovered, clicked and marquee-selected. They stay out of the skyline and spacing, `pageToSvg` omits them unless `ghosts: true`, and the UI leaves them out when printing. The option is part of the cache's `scoreKey`. Never use it for output or collision tests.
- **Collisions (`src/engrave/collide.ts`)**: every prim carries `k` (kind), `o` (owner) and `g` (groups) tags set where it is pushed (`tagFrom`/`oid` in `scene.ts`). `findCollisions(pages)` reports any overlap not in `ALLOW` (pairs of kinds, scope `own`/`any`); staff lines and untagged prims are ignored. Pairs of box-like shapes are compared by bounding box, others by outline. `test/collisions.test.ts` runs it on the whole piece; `KNOWN` there lists tolerated leftovers. New drawing code must tag its prims.
- **`src/smufl.ts`**: Leland outlines via opentype.js; `CP` maps glyph names to codepoints. `checkCodepoints()` verifies the table against the font metadata advances; run it when adding glyphs.

## Editor (`src/editor/`, `ui/`)

- **Headless editing, `src/editor/`** (testable with `node --test`, `test/editor.test.ts`):
  - `commands.ts`: pure `Score -> Score` functions on Immer drafts. A refusal throws `EditError` (message for the user). Every command leaves each voice exactly as long as its measure; `edit()` re-runs `tidy()` on the touched measures (dissolves beam/tremolo groups that lost notes, drops dangling slurs).
  - Copy and paste (`copyEvents`, `pasteEvents`, `copyMarks`, `pasteMarks` in `commands.ts`; the clipboard is in `ui/keys.ts`): a `Clip` holds the events (graces, ornaments and lyrics are event fields) with the marks that stay complete, spans that run past the copy bring their stops as `tail` (hung on the event after the pasted ones), and pasted hairpins get free ids.
  - `voice.ts`: `putEvent` writes an event at a tick: it overwrites what is there, leftovers become rests (`splitTicks`), a tick inside a tuplet descends into it (positions are *written* ticks per level), `overwrite` refuses to cut a tuplet/tremolo in half.
  - `addr.ts`: `Ref`s name things by (measure, staff id, voice id, flat event index), not by object, so they survive edits; `indexScore` maps model objects to addresses.
  - `context.ts`: clef/ottava/key/accidentals in force at a position, staff position <-> pitch, transposition.
  - `similar.ts`: "select similar", the refs of every element like a given one (same mark type, all notes, all rests ...), which the Properties panel edits together; with `by` ('fermata' | 'trill' | 'grace') the events carrying that ornament.
  - `hit.ts`: `buildHitIndex(score, engraved)` turns prims into targets via the engraver's tags (`Prim.r` = model object, `Prim.n` = head index / slur id), `hitTest`, `marquee`, `measureAt`, `snapTick` (uses `Engraved.layout`: per staff-measure x/y and column positions).
- **UI, `ui/`** (Vite + Preact + signals + CodeMirror 6; `npm run ui`): `state.ts` holds the score signal with undo history (`commit`/`run`), selection, tool settings, and the engraving effect (full re-engrave per edit, 70-200 ms on the big piece; one-system scores are re-engraved with `fillLast`). `actions.ts` holds the actions on the selection shared by the palette, Properties and shortcuts (each runs a command and commits one undoable step; an `EditError` goes to the status line), `pickers.tsx` the duration/accidental pickers both panels share, `Shortcuts.tsx` the `?` dialog (documentation only; the bindings are in `keys.ts`). `interact.ts` is the pointer state machine (select/marquee/drag head/note and rest input/spans/marks/tuplet; there are no context menus, every action is in the Properties); `ScorePane.tsx` renders pages (SVG generated only near the viewport and only when the page's selection changed) with an overlay for ghosts; `Palette.tsx`, `Properties.tsx`, `keys.ts`, `TextPane.tsx` (the score as text, hidden by default, Ctrl+E; edits re-parse after a pause into one undoable commit; the score selection is marked in the text through `writeTextMap`, which returns the text with the ranges of events, marks, tuplets and measures, keyed by `refKey`).
- In dev builds `window.__t` exposes the state signals (`score`, `hit`, `engraved`, `selection`, ...), used for scripted tests with `playwright-core` + the system Chromium (`executablePath: '/usr/bin/chromium'`, `--no-sandbox`).
- The engraver runs in the page: `ui/fonts.ts` feeds Leland to `setSmuflSource`; `loadSmufl()` is a lazy facade (and `D` in `draw.ts` a lazy proxy), so engraver modules may touch the font at import time. Nothing under `src/` may import `node:*` at top level. UI files are `.tsx` and Vite-only.
- **Playback**: `src/playback/sequence.ts` (headless, tested) turns a `Score` into timed MIDI messages (tempo map, ties merged, velocity from dynamics, hairpins ramp to the next dynamic (`readDynamicsAndPedal`), pedal -> CC64, channel per staff); `ui/player.ts` sends them to a Web MIDI output with a look-ahead scheduler and owns `playTick`/`playhead` (absolute ticks, kept across stops so play resumes). Edits while playing rebuild the sequence and carry on; a new document (`docId`) resets to the start. No built-in synth (decided against).
- Range selection of measures: the selection holds `measure` refs (Shift-click in `interact.ts` grows a run from the last clicked measure, Ctrl adds one); the Measure tab edits the whole run (`setKeySigRange`/`setTimeSigRange`, barline at the end, repeat start and break at the start, voltas on all), Ctrl+C/V copy and paste the staff contents (`copyMeasures`/`pasteMeasures`, hairpins renumbered, same lengths required).
- Not done: MIDI keyboard input, multi-staff-part scores beyond the model's own limits.

## Desktop app (`electron/`)

- The editor runs in a plain browser (the built UI from `out/ui` served by any static server) and in an Electron wrapper for the desktop. `ui/native.ts` is the one place that knows the difference: `window.native` (the preload bridge) in Electron, else the File System Access API or a file input and a download for open/save, `window.print()` for PDF, `beforeunload` for the unsaved flag. Keep new native features behind that interface with a browser fallback. `electron/main.ts` (window, MIDI permission, open/save dialogs, PDF via `printToPDF` with `preferCSSPageSize`, unsaved-changes prompt on close) and `electron/preload.ts` (exposes `window.native`; typed in `ui/native.ts`) are bundled by `tools/build-app.ts` (esbuild, into `out/app`; the main script is ESM, the preload CJS). The built UI is loaded from `out/ui` (Vite `base: './'`).
- File handling goes through `native` (see above): `openFile`/`saveFile` in `ui/App.tsx`, the path is `filePath` in `state.ts` (in a browser the file's name stands in for a path). Autosave to `localStorage` stays as crash recovery.
- Scripted checks: `_electron.launch` from `playwright-core` with `--no-sandbox`.

## Conventions worth knowing

- `examples/gewitter.txt` is generated from `gewitter.musicxml` (the reference piece covering the supported features). Regenerate it with `import` after importer changes.
- Engraving tests assert on emitted primitives (`engrave(...).pages[0].prims`), not on pixels. Visual checks are done by rendering and viewing crops; `out/` is git-ignored.

## Comment and blank-line style

- Every comment is a complete sentence that starts with a capital letter and ends with punctuation. The exception is a comment that starts with an identifier or code (`` `placed` holds ``, `x0 and x1 are read ...`, `eb2 in m33 ...`). This includes trailing comments on fields and statements (`// This is the voice id.`), not only block comments.
- Comments on functions (declarations, and arrow functions bound to a `const`) use `/** ... */`, not `//`. A `//` comment is for explaining code inside a body or for a section.
- No `// ---- name ---` banner headers. A section of a file starts with a plain `//` comment of a few lines that says what the section is for and how it relates to the rest, followed by a blank line, so that it cannot be mistaken for the doc comment of the first function below it.
- A file starts with a header comment (what the module is for, how it fits the pipeline), then a blank line, then the imports.
- Blank lines on the top level of a file (checked by `tools/blanklines.ts`, part of `npm run lint`): items are separated by exactly one blank line, except a run of one-line declarations without comments (imports, constants, type aliases); a doc comment sits directly above its declaration; a `/** */` comment is never left standing alone. Biome already collapses repeated blank lines and cleans up the edges of blocks; blank lines inside functions and classes are not checked.
